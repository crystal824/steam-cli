Release notes are now **written**, not dumped from commit titles.

## What changed

**Release pages are curated.** The workflow now publishes `docs/releases/<tag>.md`
as the release body when that file exists, falling back to the generated changelog
otherwise. This page is the first one produced that way; `docs/releases/README.md`
describes what good notes contain.

**The changelog explains itself.** `cliff.toml` now prints each commit's description
under its title and skips housekeeping commits (`chore:`), so `CHANGELOG.md` reads as
a set of explained changes instead of a bare list of titles such as
"chore(release): 0.2.1".

**Template fixes reach older tags.** The release job reads `cliff.toml` from `main`
rather than from the tag's own tree. Formatting is tooling, not released code, so
re-publishing an old tag now produces the current layout instead of the layout frozen
at that tag.

**Releases can no longer roll the changelog backwards.** The automatic `CHANGELOG.md`
commit only runs for the newest tag, so re-running an older release cannot overwrite a
newer changelog.

## Upgrading

Nothing to do. This release changes release tooling only — the CLI, the Python
package and the skill archive behave exactly as in 0.2.1.
