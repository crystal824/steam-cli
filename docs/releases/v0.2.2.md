# v0.2.2

**发布说明改为人工撰写，并支持中英双语 / Release notes are now written by hand, in Chinese and English.**

## 中文

这个版本不改变 CLI 的行为，只改**发布说明怎么产生**——之前 Release 页展示的是自动汇总的提交标题（例如 `chore(release): 0.2.1`），看不出这个版本到底改了什么。

**1. 发布说明人工撰写，并优先使用**

发布时，CI 会优先把 `docs/releases/<tag>.md` 作为 Release 正文；没有该文件才回退到按提交自动生成的 changelog。本文这份就是第一篇这样产出的说明。

**2. CHANGELOG 自己会说话**

`cliff.toml` 现在会在每条标题下附上该提交的详细描述，并**跳过 `chore:` 这类内部琐事**。仓库里的 `CHANGELOG.md` 因此是一份"带解释的变更记录"，而不是标题清单。

**3. 排版与文案的修复能作用到已发布的版本**

发布任务改为从 `main` 读取 `cliff.toml` 和 `docs/releases/`（它们属于工具与文档，不是被发布的代码）。好处是：重发旧 tag 时会用当前排版；**想修正某个已发布版本的文案，只要改文件再重推 tag，不需要任何 token**。

**4. 重发旧版本不会把 CHANGELOG 倒退**

自动提交 `CHANGELOG.md` 的步骤只在"最新 tag"时执行，所以重跑历史版本绝不会覆盖更新的变更记录。

**升级说明**：无需任何操作。本版本只影响发布流程，CLI、Python 包与技能归档的行为与 0.2.1 完全一致。

## English

This release does not change what the CLI does. It changes **how release notes are produced** — previously the release page showed the auto-grouped commit titles (`chore(release): 0.2.1`, and so on), which said nothing about what actually shipped.

**1. Notes are written by hand and preferred**

CI publishes `docs/releases/<tag>.md` as the release body when that file exists, falling back to the conventional-commit changelog otherwise. This page is the first one produced that way.

**2. The changelog explains itself**

`cliff.toml` now prints each commit's description under its title and skips housekeeping commits (`chore:`), so `CHANGELOG.md` reads as a set of explained changes rather than a bare list of titles.

**3. Formatting and wording fixes reach published releases**

The release job reads `cliff.toml` and `docs/releases/` from `main` (both are tooling and documentation, not released code). Re-publishing an older tag therefore picks up the current layout — and **correcting the notes of a published release is just edit-the-file and re-push the tag, with no API token**.

**4. A re-release can no longer roll the changelog backwards**

The automatic `CHANGELOG.md` commit only runs for the newest tag, so re-running an older release cannot overwrite a newer changelog.

**Upgrading**: nothing to do. This release only changes release tooling; the CLI, the Python package and the skill archive behave exactly as in 0.2.1.
