# v0.2.7

**干净安装即可用：内置绕过第三方库的过时校验，并修正凭据说明与错误提示 / A clean install now works, with corrected credential docs and error hints**

## 中文

**1. 全新安装后，库/统计/好友功能不再失败**

上一版有个新用户必踩的坑：`pip install` 之后 `steam stats summary`、`library list`、`friends list` 会直接失败——

```
network_error: a network error occurred while contacting Steam
Method requires 'appids_filter' to be set
```

原因是 ValvePython 会拿 Steam 的 `GetSupportedAPIList` 元数据校验每一次调用，而那份元数据已经与真实接口不一致：它把「可以省略」的参数标成了必需。此前唯一的解法是**手工给 site-packages 打补丁**（见 `patches/`），这不是用户该对依赖做的事。

现在变通逻辑内置在包里：`src/steam_cli/_compat.py` 在元数据加载完成后把这些参数标记为可选，缺失的参数就不会被发送，改由 Steam 自己做真正的校验——效果与原来的补丁相同，但不再需要用户动手。加上 `steam login` 自 0.2.6 起已不再走 ValvePython 的退役登录路径，**两处补丁都不再需要**；`patches/` 降级为历史留档（仍可用于直接使用该库的场景）。

**2. 凭据说明修正（此前会误导）**

文档曾写「库 / 统计 / 好友只需 Web API Key」，实际这些命令**既需要 Key 也需要登录态**：Key 用于授权调用，登录态提供你的 SteamID。按旧文档操作会撞上 `not_authenticated`。现在两张 README 的命令表按代码事实逐条标注，并新增「排错速查」把每种结构化错误映射到应当执行的命令。

**3. 错误提示不再教用户跑不存在的命令**

`errors.py` 里的提示原文是 `steam auth login` / `steam auth set-key`（该子命令并不存在）。现在分别指向 `steam login`、`steam set-key`，会话过期则指向 `steam refresh --remint`。

**4. 多词游戏名不再需要引号**

`steam search black myth` 此前会报 `Got unexpected extra argument(s) (myth)`，必须写成 `steam search "black myth"`。名称类位置参数现在都接受多词（`search` / `app` / `price` / `library has` / `review summary`），`client.join_terms()` 负责拼接。

**5. README 按新用户视角重写**

新的顺序是：你需要什么 → 安装（明确「无需任何额外步骤」）→ 30 秒试跑（免凭据命令）→ 接入账号 → 命令与凭据表 → 看懂一款游戏的评价 → 商店区域 → 安全策略 → 排错速查 → 代理 → 仓库结构 → Hermes 技能包 → 参与开发。新增的「仓库结构」表明确说明 `patches/`、`tools/`、`skill/`、`scripts/`、`tests/` 对**使用** CLI 都不需要；开发者内容（CI 门禁、构建、发版流程）改为链接到 `CONTRIBUTING.md` / `docs/development.md` / `docs/releases/README.md`，不再在 README 里重复维护。

**升级说明**：安装新版本即可，无需任何迁移。若你此前手工给 site-packages 打过补丁，可以保留——`_compat.py` 只放宽参数可选性，两者不冲突。行为上的变化只有两处：多词名称不再需要引号；报错提示文本改为真实命令。测试规模 107 项，ruff / format / mypy / pytest 四道门禁全绿。

## English

**1. A clean install can use the library features again**

The previous release had a trap that hit every new user: right after `pip install`, `steam stats summary`, `library list` and `friends list` failed with

```
network_error: a network error occurred while contacting Steam
Method requires 'appids_filter' to be set
```

ValvePython validates every call against Steam's `GetSupportedAPIList` metadata, and that metadata no longer describes the live endpoints: it marks parameters as required that Steam is happy to receive omitted. The only documented remedy was to hand-patch site-packages (`patches/`) — which is not something a user should have to do to a dependency.

The workaround now ships inside the package: `src/steam_cli/_compat.py` flags those parameters optional right after the metadata is loaded, so absent parameters are simply not sent and Steam does the real validation — the same effect as the patch, without the manual step. Together with `steam login` dropping ValvePython's retired login path in 0.2.6, **neither patch is needed any more**; `patches/` is historical reference (still useful if you drive that library directly).

**2. The credential documentation was wrong**

It claimed the library / stats / friends commands need only a Web API key. They need the **session too** — the key authorises the call, the session supplies your SteamID — so following the old docs produced `not_authenticated`. The command tables in both READMEs now say exactly what each command needs, and a new troubleshooting table maps every structured error to the command that fixes it.

**3. Errors no longer point at a command that does not exist**

The hints in `errors.py` said `steam auth login` / `steam auth set-key` (there is no `auth` subcommand). They now name `steam login`, `steam set-key`, and `steam refresh --remint` for an expired session.

**4. Multi-word game names need no quoting**

`steam search black myth` used to answer `Got unexpected extra argument(s) (myth)`; only the quoted form worked. Name arguments are variadic now (`search`, `app`, `price`, `library has`, `review summary`), joined by `client.join_terms()`.

**5. The READMEs were rewritten newcomer-first**

New order: what you need → install (explicitly "no extra steps") → a 30-second try-it with credential-free commands → connecting an account → the command/credential table → reading a game's reception → store region → safety → troubleshooting → proxy → repository layout → Hermes Skill → contributing. The new layout table spells out that `patches/`, `tools/`, `skill/`, `scripts/` and `tests/` are irrelevant to *using* the CLI, and contributor material (CI gates, builds, releasing) moved behind links to `CONTRIBUTING.md` / `docs/development.md` / `docs/releases/README.md` instead of being duplicated in the README.

**Upgrading**: install the new version; nothing to migrate. If you had hand-patched site-packages, you can keep it — `_compat.py` only relaxes optionality, so the two do not conflict. The only behaviour changes are that multi-word names no longer need quotes and error hints name the real commands. 107 tests, all four gates green.
