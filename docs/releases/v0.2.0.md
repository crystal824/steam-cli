Steam retired or changed several of the endpoints this CLI was built on. Login, CD
key activation, wishlist reads and store lookups were all affected, and the failures
looked like bad credentials or bad keys rather than dead endpoints. **0.2.0 reworks
those paths and adds the tooling needed to log in, re-authenticate and verify an
activation.**

Nothing changes about how you call the CLI; the commands work again on the current
Steam backend.

## CD keys activate again

`steam activate` posted to `/account/registerkey`, which is only the HTML form page.
Every activation therefore ended in `endpoint_unavailable`, no matter how good the
key was, and a perfectly valid key looked broken.

It now posts to `/account/ajaxregisterkey/` — the endpoint the store front-end
actually uses — parses the JSON response and maps every rejection code:

| Code | Meaning | How it is reported |
|---|---|---|
| — | success | the activated product name is printed and written to `audit.log` |
| 15 | already activated by another account | `already_activated` |
| 9 | already owned by this account | `already_owned` — the key was consumed earlier, not a failure |
| 14 | invalid key | `invalid` |
| 13 | region locked | `region_locked` |
| 53 | rate limited | `rate_limited` |
| 24 | base game required | `base_game_required` |
| 4 | retry after 30 minutes | `retry_later` |

Re-submitting a key is now a safe check: if it had never worked you would get
`invalid`, and if it worked you get `already_owned`.

## Wishlist reads work again

The store endpoint `wishlistdata` answers **302 for every request** now. Wishlists are
read through `IWishlistService/GetWishlist/v1` instead, and display names are resolved
with concurrent single-appid lookups (batched `appdetails` returns HTTP 400 for any
comma-separated list, and `GetAppList` is 404/403). Names are cached in
`~/.config/steam-cli/appnames.json`, so the first run takes a few seconds and later
runs are fast.

## Crashes with multi-domain session cookies

Steam mirrors `sessionid` and `steamLoginSecure` across the store, community and help
domains. `requests` refuses `cookies.get()` when a name exists more than once, so
`activate`, `friends`, `review` and `wishlist` crashed with `CookieConflictError` even
with a perfectly good session. All lookups now go through `auth.cookie_value()`, which
iterates the cookie jar.

## Achievements stop crashing

`ISteamUserStats` returns `percent` as a string; formatting it as a float raised
`ValueError`. Values are coerced, and unparseable ones sort last and print as `-`.

## Documentation corrected

Every `steam auth <command>` reference was wrong — there is no `auth` subcommand. The
commands are top level: `steam status`, `steam set-key`, `steam login`, …

## New tools

- **`tools/steam_modern_login.py`** — logs in through `IAuthenticationService`
  (RSA key → BeginAuthSession → approve in the mobile app or enter a Steam Guard code
  → poll → `finalizelogin` → settoken). Needed because ValvePython's `WebAuth` posts
  to the retired community `/login/dologin/`: it still reports success after a correct
  password and Steam Guard code, but mints a session that authenticates nothing.
- **`tools/steam_remint_session.py`** — re-mints session cookies from the stored
  refresh token, with **no password and no 2FA**. Run it whenever `steam status`
  reports the session is no longer valid.
- **`tools/check_licenses.py`** — lists licences with acquisition date and method
  (`Retail` = key, `Steam Store` = purchase, `Gift/Guest Pass` = gift). Use it to
  confirm an activation really landed: the library API has no acquisition timestamp.

## Internals, tests and docs

- `docs/steam-endpoint-changes-2026.md` — endpoint-by-endpoint breakdown: what
  changed, the symptom it produces, and the fix.
- Unit tests moved to the JSON activation contract and now cover the result-code
  mapping, the ajax endpoint and its headers, cookie lookups against mirrored
  domains, and the achievement percentage coercion.
- Two local patches are documented in `patches/` for the parts of the installed
  `steam` package that lag behind Steam (`webauth._finalize_login` and
  `webapi` required-parameter validation).
